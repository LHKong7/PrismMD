# 2026-08-25 · 阶段 3：SQLite → Vault 迁移工具

> [Vault 迁移计划](./2026-08-25-vault-migration-plan.md) 的第三阶段。
> 本阶段起 Vault 模式**可以真正启用**：设置里出现迁移入口，
> 迁移成功后 `storageMode` 切换，重启后从 Vault 读。

## 背景 / 问题

阶段 2 造好了 Vault 后端但没有接线，因为把真实工作区切过去需要两样东西：
一条把数据搬过去的路径，以及一个**能证明搬完整了**的校验。

「看起来搬成功了」在这里毫无价值。这是全应用唯一一个一次性触碰用户全部笔记的
操作，而失败是静默的：标题里带斜杠的笔记落到了别的文件名下、名字撞上 Windows
保留字的文件夹被跳过、某个空内容的页面被某处的 `.filter(Boolean)` 丢掉。
几周后才发现，那时备份已经轮转掉了。

## 设计决策

### 迁移不自己判断成功

`migrateSqliteToVault()` 不决定自己成功与否，`compareSnapshots()` 决定。
两侧用**同一份代码**测量，任何一处不同都拒绝签字，`ok` 不为 true 就不切换
`storageMode`。

校验项：逐篇内容 hash、标题、所在文件夹、格式、二进制字节（**逐字节比对，
不是比大小**——长度正确的截断副本正是大小检查会放过的那种损坏）、
文件夹层级、标签集合，以及**能解析的链接数**。

链接按「能解析的数量」比，而不是「链接总数」：指向从未写过的笔记的链接
两边都解析不了，那不是迁移问题；**迁移前能解析、迁移后不能**，说明某篇笔记的
标题在途中变了，那是。

笔记按 **id** 匹配，绝不按路径或标题。迁移**允许**改文件名（标题里的 `/`
没法原样变成文件名）和给重名编号（`Untitled 2.md`），唯独不允许弄丢笔记。
按路径匹配会把每一次合法改名都报成丢失，真正的丢失反而被淹没。

### 校验在第一次真跑时就抓到一个真 bug

写完立刻跑，红了。原因：**二进制文档在 Vault 里没有稳定身份**。

`readIntoCatalog` 对 PDF 是这么写的：

```ts
const existing = getEntryByPath(this.db, relativePath)
id = existing?.id ?? crypto.randomUUID()
```

catalog 是缓存，重建时是空的 → PDF 每次都拿到新 id。当时我给这行写的注释是
「丢了 PDF 的 id 只是要重新抽取一次文本，不会断链接——没有东西链接到 PDF」。
**这句话是错的**，错在两处：

1. 抽取文本按 page id 缓存，换 id = 文档变得搜不到；
2. **标注**按 page id 存，换 id = 用户在 PDF 上划的高亮全部失联。

而文档本身还好端端躺在那里，看不出任何异常。

修法：新增 `.prism/binaries.json`，路径 → uuid。这让 `.prism/` 里出现了
**第二份主数据**（另一份是 `annotations/`）——`ui.json` 丢了只是退化成按名排序，
这个丢了就是丢高亮。诚实的局限也写下来了：**外部工具移动 PDF 会让它换 id**，
因为没法往 PDF 里写东西，这一点比 Markdown 差，无法通过设计绕开。

同时给契约补了两条断言（现在 40 条），因为这个 bug 是**校验器**抓到的，
契约测试没抓到——那正说明契约缺了这一条。

### 抽取文本的归宿（D3 落地）

PDF 的可搜索内容是抽取出来的文本，而它**没法写回 PDF 里**。这是 Vault 模型里
唯一一处「笔记的可搜索内容不在 Vault 中」。

落地为 `note_text_cache` 表，并明确它是「可重建，但**只能懒重建**」：
抽取跑在渲染进程的 pdfjs 里，主进程启动时做不到。所以「重建索引」对二进制页面
是清空、等下次打开时回填，而不是像别的东西那样一遍重算。

迁移会把这些文本一并带过去，否则 PDF 在迁移落地的那一刻起就搜不到了，
而且没有任何提示。

### 为什么迁移期间必须拒绝写入

渲染进程是**防抖自动保存**的。迁移正在逐篇复制时落下一次保存，会写进
**正在被离开的那个库**，新库永远看不到它。这不是假设——用户盯着进度条继续打字
就会发生。

所以 `areWritesSuspended()` 期间写入直接**报错返回**：用户看到一次保存失败可以
应对，静默接受则是无声地丢掉那一段。

### 顺手修掉的一个真 bug

`registerWorkspaceHandlers()` 原本在注册时 `const repository = getNoteRepository()`
把仓储**捕获**下来。迁移会在运行时换掉活动仓储，捕获的那个就成了旧的——
于是迁移之后的每一次写入都会写进用户刚刚迁走的数据库，而且**每一次都返回成功**。
改成每次调用时解析（`const repo = () => getNoteRepository()`）。

### 页面 id 原样带过去，于是绝大多数表不用迁

`annotations` / `page_versions` / `page_meta` / `doc_summaries` / `muse_cards`
全部以 page id 为键。id 写进 frontmatter 原样带过去之后，**这些表一张都不用动**。
反过来说，如果迁移时重新生成 id，这些表会**静默**全部失联，一条错误都不会报。

## 改动清单

### 新增 `electron/migration/`

| 文件 | 作用 |
| --- | --- |
| `migrationValidator.ts` | 纯函数：快照 + 比对，10 类问题码 |
| `migrationJournal.ts` | 磁盘上的进度记录，成功即删；**不做自动恢复**——一次用户主动发起的一次性操作，无人值守续跑更可能把问题放大。它买到的是「事后状况可读」 |
| `sqliteToVault.ts` | 备份 → 建目录 → 写笔记 → 写侧车 → 校验 → 原子换入 |

暂存目录是目标的**同级兄弟**，所以最后一步是同一文件系统内的 `rename`——
原子的，不可能出现「一半笔记搬过去了」的中间态。

### 新增

- `electron/vault/binaryIds.ts` —— `.prism/binaries.json`，二进制文档的稳定身份
- `electron/services/storageService.ts` —— 启动时解析存储模式、执行迁移、
  暂停写入。**只有这一处**决定应用指向哪个库
- `electron/ipc/storageHandlers.ts` + preload + Settings 里的 Vault 区块（中英双语）

### 改造

- `ipc/workspaceHandlers.ts` —— 仓储改为每次调用解析；6 个写入通道加暂停守卫
- `vault/markdownVaultRepository.ts` —— `readIntoCatalog(path, knownId?)`；
  二进制走注册表；`scan()` 顺带清理失效的注册表项
- `vault/vaultCatalog.ts` —— `note_text_cache`
- `services/settingsStore.ts` —— `storage: { mode, vaultPath, migratedAt }`
- `main.ts` —— 开窗前 `await initStorage()`

### 一个刻意不做静默降级的地方

设置里写着 Vault 但文件夹不在（外置盘没挂载、被移走），**不会**悄悄退回 SQLite
给你一个空工作区。以为自己笔记没了的人会做出不可逆的操作。
状态里带着实情，设置面板明说。

## 验证方式

```bash
npm test        # 452 passed（新增 42：validator 20 / 端到端迁移 18 + 契约 2 + 二进制身份）
npm run typecheck
```

端到端测试跑在**真实的 SQLite 工作区和真实目录**上——这套东西所有值得抓的 bug
都住在两者之间的缝里。

失败路径的测试用的是**诚实的故障注入**：通过 `onProgress` 钩子，在写入者报告
完成之后、校验读回之前，从暂存目录里删掉一个文件。这模拟的是「一次被 catch
吞掉的权限错误 / 同步客户端吃掉一个文件 / 未来重构写入循环时的 bug」。

> 第一版这个测试写的是「让 `listPages` 第二次返回少一篇」，跑出来是绿的——
> 因为 `listPages` 全程只调用一次。测试本身的前提是错的，改掉了。

变异测试确认断言真的会咬：

| 变异 | 结果 |
| --- | --- |
| 校验失败也照样换入 | 3 条红 |
| 不写二进制 id 映射 | 1 条红 |
| 跳过没有笔记的空文件夹 | 1 条红 |
| 不带抽取文本 | 1 条红 |

## 后续项

- **阶段 4**：`knowledgeService` 已经走仓储，所以索引本身不用改；要做的是把
  `VaultWatcher` 接上，让外部改动实时反映，以及标注迁到 `.prism/annotations/`。
- **标注仍在 workspace.db**：id 带过去了所以功能正常，但备份 Vault 文件夹
  **不包含标注**。这是 D4 尚未兑现的部分，阶段 4 要连读路径一起切。
- **中断的迁移只报告不恢复**：journal 能让事后状况可读，但没有「继续/回滚」按钮。
- **迁移无进度粒度**：`onProgress` 只报写入阶段；大工作区的校验阶段是静默的。
- **不能迁回去**：从 Vault 退回 SQLite 没有实现。原库还在（只读存档），
  但没有 UI 路径。
